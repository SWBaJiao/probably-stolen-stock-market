## 日程与保存

默认提前排定未来 7 日，每 2～4 个游戏日一条，同一模板冷却 14 日。选取不读取持仓，随机源独立于每日行情和 NPC 抽签。旧存档从首次接入以后安排，不补造过去事件。

每次事件持续 2～4 日，主冲击日在持续期内随机确定并保存。此前可能轻微预热，但不会公开事件标题、公司影响表、内部 ID 或未来日期。公开日与主冲击日一致，此后新闻、公司详情和价格原因可以展示已公开事实。

预热、延续和结束恢复沿用既有阶段规则；每实例保留 20%～50% 的实际事件偏移。原版与专用事件的同公司主冲击共用每日 ±15% 限额，恢复仅归属实际施加的因子。每次报价、日程、强度、种子、主冲击和核验结果随原版存档保存，读档不会重抽。

原版活动列表只管理原版事件。专用事件由独立日程结束，原版列表缺少专用 ID 不会使其提前结束。

以下配置位于游戏侧 `UserData/MelonModTemplate/market-config.json`，缺失字段使用新版默认值，现有文件不会被部署覆盖。

| 配置 | 默认值 | 含义 |
|---|---:|---|
| `EnableStockEvents` | `true` | 启用专用事件排程 |
| `StockScheduleDays` | `7` | 提前排程天数 |
| `StockEventIntervalMinDays` / `StockEventIntervalMaxDays` | `2` / `4` | 事件间隔范围 |
| `StockTemplateCooldownDays` | `14` | 同一模板的冷却天数 |
| `StockDurationMinDays` / `StockDurationMaxDays` | `2` / `4` | 持续天数范围 |
| `StockIntensityMin` / `StockIntensityMax` | `0.8` / `1.2` | 基础影响的强度范围 |
| `EventShockDailyLimit` | `0.15` | 同公司每日主冲击净幅上限 |
| `StockEventTemplates` | `20` 个模板 | 标题、经营故事、主公司、行业及公司基础影响 |

## 闻舟、剑清酱与交付

两位角色继续使用共用号码 **731206**，确认后随机一位次日来访，分别保存来访和信誉。第 D 日预约、第 D+1 日上门时，只出售第 D+2～D+4 日可核验的消息。专用事件以已保存的主冲击日作为内幕观察日；电话和购买操作不会为了出售消息而新造事件。

闻舟按行业来源和信誉生成真假；剑清酱保持默认 70% 逐公司反向、30% 与真实事件一致。一次多公司线索共用一个真假结果，反向时对涉及公司逐一取反。正确与错误消息使用相同格式，不披露精确幅度。

购买成功后沿用原生情报购买、柜台 `handnote` 纸条、内幕档案和次日起连续三日的日历提醒。柜台无位置时等待补交，不重复收费；跳过成交对话、遣散和保存载入走同一个幂等交付入口。

纸条、日历和档案只读取已购安全投影，展示原始预测、来源、信誉、购买日、观察窗口和核验状态。已交付纸条在重新阅读时更新核验详情。原始预测不改写；公开后再追加事件新闻和预测／事实方向对照。取消或无法确认时记“未能验证”，不扣信誉。

## 游戏内验收

1. 进入旧存档，确认没有过去事件突然补跳；保存重载后报价、日程和行情保持不变。
2. 持股市面板拨打 731206，确认预约；次日由闻舟或剑清酱提供一条报价，付款前不暴露公司方向和真实日期。
3. 购买后核对只扣一次费用，柜台纸条、内幕档案、次日起三日日历显示相同预测；柜台满、跳过对话及读档后交付不重复。
4. 主冲击日前，“市场新闻”和公司介绍不能看到未来事件；公开后显示事实、关联公司与阶段。分化事件应能同时令不同公司涨跌。
5. 在纸条交付后保存，待事件公开重新读纸条及日历，确认结果更新、原始预测保留；其他行情改变最终股价不干扰事实核验。
6. 普通商品价格、原版事件队列、普通纸条和其他 NPC 正常；切档、关闭与卸载后没有残留自有窗口或回调。

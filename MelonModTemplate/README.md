# 股市 Mod 开发与使用

程序集保持 `MelonModTemplate.dll`，模组显示名称为 `Probably Stolen Stock Market`，版本 `0.9.1`。覆盖旧模板 DLL 后只会加载一个入口；无需同时保留旧模板。

## 安装与构建

目标环境为本机已生成代理的 Demo 0.46D / Unity 2021.3.45f2 / MelonLoader 0.7.3 / Windows x64 .NET 6.0.36。其他版本需要重新核对代理接口。

复制 `Game.local.props.example` 为 `Game.local.props` 并填写游戏目录。CrossOver 下填写 macOS 可访问的容器目录，不填写 Windows 的 C 盘路径。本地配置、生成 DLL、缓存和游戏代理均不提交到 Git。

```sh
dotnet build MelonModTemplate/MelonModTemplate.csproj -c Release
```

默认启用 `UseGameInterop=true`，引用游戏生成的代理以及加载器提供的 Harmony/Il2CppInterop，引用不随模组复制。输出自动部署为：

```text
<游戏>/Mods/MelonModTemplate.dll
<游戏>/UserData/MelonModTemplate/Assets/market-config.default.json
<游戏>/UserData/MelonModTemplate/Assets/Textures/Items/stock_market_terminal.png
```

只构建加 `-p:DeployOnBuild=false`；复制调试符号加 `-p:DeployDebugSymbols=true`。构建不会启动游戏。

## 第一次使用

1. 进入存档，等待背包出现“股市面板”；背包满时腾出空间，系统每 10 秒重试。
2. 双击道具打开面板。旧版记录了道具却找不到时，在游戏中按 `Ctrl+F8` 显式补领；会优先采用已有道具，不删除便笺。现货交易默认开放，可以直接买入和卖出已持有股票。
3. 检查 `[股市交易]` 的可交易状态。默认无需首次保存重读；`RequireSaveReloadVerification=true` 可启用严格验证，要求保存后重新载入。余额不足、无持仓或资金补偿失败时显示具体原因。
4. 卖出或买入商品，成交与遣散后股价应保持不变；进入次日后观察昨日成交量引起的轻微变化。股票操作和情报费不会计为商品交易，事件按固定的行情日程独立影响价格。

窗口关闭可点击“关闭”或按 Escape。`Ctrl+F8` 只请求补领道具，不直接打开交易窗口。面板显示期间阻断主要原版买卖、拖拽及顾客操作，关闭后恢复鼠标状态。最终输入穿透情况仍需游戏内验证。

面板通过游戏的 `CustomUIManager` 和 `CustomUIBuilder` 创建独立原生窗口。优先使用已有控件预制件；缺少 SDK 模板时，以原生 UGUI 控件和游戏已加载的窗口、按钮图像及 TMP 字体建立本 Mod 的通用模板。行情、持仓、内幕、流水分为四个页面，交易仍通过原有资金和存档门控接口提交。

文字优先沿用游戏预制件的 TMP 字体和样式；中文覆盖检查及本窗口的字体回退记录在原生面板日志中。原生控件初始化、实际大小和输入效果需要在当前游戏中验证。

弹窗采用不透明深蓝背景、浅白正文、浅蓝标题及选中边框。按钮区分普通、选中、悬停、按下和禁用状态，禁用文字仍保持可读；涨红跌绿，可交易状态为绿色，不可下单原因与操作提示为黄色。图表、坐标和悬停框使用相同主题，悬停正文为 14 号字并带浅蓝细边框。

行情页在宽屏显示左侧公司列表及右侧图表与委托，窄屏纵向排列；持仓卡片按宽度分为一列或两列。图表可切换“当日分时、近 7 日、近 14 日、近 30 日”。当日分时按真实发生顺序连接开盘/接入基准、包含昨日成交影响的每日行情与事件变价，横轴为采样次序，不虚构分钟时刻。商品成交和遣散不再追加变价采样；无事件日的曲线采样较少属于正常行为。当天所有记录随存档保存，独立于总价格历史的长度限制，跨日开始新曲线；旧档只恢复可确认的当天样本并提示记录不完整。

7/14/30 日继续使用日 K 线，显示开高低收、影线和当前价线。上涨红色、下跌绿色、平盘灰色；旧存档及首次盘中接入日只显示灰色收盘标记，未知开高低为 `—`。正常后续游戏日开始积累完整 OHLC；当天尚未收盘的记录随实际行情继续变化。

鼠标移入图表绘图区可查看最近横轴采样：分时提示采样序号、价格及变价原因；日 K 线提示游戏日与开高低收。旧档未知值保持 `—`，当日记录标注未收盘。提示按帧响应并限制在窗口内，离开、切换、滚动裁出绘图区或关闭窗口后隐藏。

## 公司和商品

默认 10 家公司：丰禾供给、清泉循环、白塔医疗、星锻工业、远星科技、环宇商贸、霆光能源、晨星物流、安盾防务、聚合材料。

商品只按真实类型映射，不通过显示名称猜测。已核实类型包括 FOOD、WATER、MEDICAL、MACHINE、MATERIAL、BASIC_MATERIAL、MODULE、ENERGY_CELL、CHEMICAL_SUPPLIES、LUXURY_ITEM、WATER_PURIFICATION_SUPPLY、FILTER、WEAPON。空瓶如果没有 WATER 类型，不会自动算作饮用水。

同一分类内多个标签只算一次；命中多个分类时平均各行权重，总影响不随标签数量增加。成交以真实资金变化及调用范围确认，嵌套回调去重；无法确认的成交记录探针并跳过。

成交以实际成交金额衡量交易量，按商品权重累加当日各公司的净信号，玩家卖出为正、买入为负，同日跨顾客买卖先抵消。新一天只结算前一天的信号，采用 `TradeDailyLimit × 净信号 / (SignalScale + |净信号|)` 递减计算，默认成交影响上限为 ±2%；再叠加基础波动与估值回归，常规日变动合计限制在 `DailyLimit`，默认 ±3%。事件按独立日程变价，大跳不受常规日上限限制。未遣散顾客的已成功成交也计入当天，保存重载和重复日期回调不重复结算。升级旧档仅迁入仍未结束会话的待结算信号，旧版已结算行情不追溯重算。

新增配置 `TradeDailyLimit` 默认 0.02，旧配置缺失时使用此默认值；`CustomerLimit`、`RetailDailyLimit` 仅保留旧配置兼容，不再控制行情。股票初始价 100，手续费 0.5%，最低 1 游戏币；买入支出向上取整，卖出净收入向下取整。

事件激活时会固定一份行情计划：在当前可观察日到实际预计最后持续日之间，均匀随机选一天集中大幅跳价，包含当天，整次事件最多一次。持续 3 天的事件可能在第 1、2 或 3 天大跳；未知时长或永久事件使用 `EventShockWindowDays`，默认前 5 天窗口。此前每天以默认 65% 的概率轻微预热，幅度为配置冲击的 5%，单事件最多 0.5%；大跳当天不再预热或延续，之后按配置冲击的 10% 小幅延续，单事件每日最多 0.75%。预热和延续共用配置冲击幅度 25% 的累计预算。

事件实际结束后，从下一游戏日逐步消退，每天尝试修复剩余可消退影响的 25%；同公司所有事件的预热、延续与修复共用每日 ±1% 上限，大跳独立计算。如果事件在计划大跳前结束，取消尚未发生的大跳，只对已经发生的预热做部分修复，不在结束后补跳。

每次事件只抽取一次 20%～50% 的保留比例，同一事件涉及的公司共用该比例，比例与实际已施加的偏移随存档固定。结束后保留这部分长期影响，利空留下折价、利好留下溢价。例如只看总计 −10% 的事件影响，最终保留 2%～5% 的折价；其他成交、日常波动和事件仍独立影响实际价格。估值回归基准包含已保留的事件因素，不会继续把它全部修复到最初的 100。回归仅消退该次事件的偏移，不回撤商铺成交或其他事件造成的变化。

可配置 `EventShockWindowDays`、`EventPreheatChance/Scale/Limit`、`EventRetentionMin/Max`、`EventContinuationScale/Limit/Budget`、`EventRecoveryRate` 和 `EventDailyDriftLimit`。大跳日、预热随机结果和保留比例随存档固定，不因读档或重复激活重抽；重复日期不追加同日影响。真实激活列表决定持续或结束状态，原版持续 3 天即生效日和之后两天，不多续一天。旧版已经完成首冲的事件按已跳价迁移，不重新排大跳；缺少旧冲击明细时只跟踪升级后的新增影响。

价格保留两位小数；极低股价若最小 0.01 的变化已超过日上限，修复会暂缓，等待后续价格允许，不突破上限或记录未实际发生的回撤。

内幕仍按原事件是否实际发生及其影响方向核验，不等待股市集中跳价。新生成线索会注明消息可能在观察期内落地、行情反应可能滞后；不会公开未来大跳日期或目标价格。

## 事件与内幕

显式事件规则优先。默认已核实并配置 `badNutrifruitHarvest`、`bm_illegal_weapon_shipment`、`rev_mobilization_secret`。未知事件如果带真实 `negociationDatas.itemType/value`，会按商品价格冲击与公司交叉权重生成影响：价格修正乘 `StructuredEventScale`，单家公司限制在 `StructuredEventLimit` 内。它是商品售价冲击对公司行情的玩法近似，具体企业的受益或受损关系应使用显式规则覆盖。没有结构化价格数据的未知事件不猜测影响。

持有本存档的“股市面板”（股市探针入口道具）后，关闭股市窗口，在原版电话簿点击“闻舟”快速拨号，或手动拨打 **731206**。拨通后出现原生确认窗口，点击“预约明日到访”才创建预约；取消、挂断、重拨或切档都会使旧确认失效。电话听筒状态栏只显示“通话中”，详细反馈写入日志；可在“内幕档案”查看号码与预约状态。原面板邀请按钮已移除，掮客不再自动来访。

预约当下按次日到访后的未来 3 日窗口选择已有排程事件，固定来源、报价、真假及外观。例如第 41 日拨号，预约第 42 日，只考虑第 43～45 日的有效关联事件；没有可售线索就不会预约。重复拨号与保存重载不重抽，次日开门后追加到顾客队尾。错过日期或线索取消会显示失效，完成并遣散后可以预约次日。

掮客显示为“闻舟 · 行情掮客”，初次实际见面会自我介绍，介绍状态随存档保留；电话联系不会提前标记见过面。介绍后打开原版情报购买窗口，默认 50 游戏币；付款前只展示消息来源、商品类别与价格。内幕付款沿用保存重读验证要求，验证未通过不能付款。普通顾客不提供股市报价。电话只接管专号，快速拨号条目仅是临时 UI，不写原版联系人存档，也不向原版未来顾客队列写入专属 ID。

购买后给出商品关联型或指定公司型的股票涨跌预测，不同公司可以方向不同；真假内容句式一致，假消息反转预测方向。掮客转售的消息归属于实际来源；当前没有可确认稳定的个人身份，因此信誉按角色类型和阵营累计，并在界面标注。来源必须匹配披露行业或为泛来源，历史验证记录会更新信誉。

付款成功即保存购买记录，在购买次日起连续三日登记日历提示。成交对话末句提供原生 `handnote` 纸条，使用柜台交付及游戏纸张阅读界面；柜台满时等待空位，跳过对话、遣散或读档后仍走同一交付入口。插入结果不确定时停止重复创建。纸条丢失不影响档案和日历，点击日历仍可阅读。

日历只添加 Mod 显示记录，不改变真实事件排程、公开状态或价格影响。事件发生后按其对目标公司的实际影响方向判定属实或失实，一条多公司情报只更新一次来源信誉。取消或无法核实记为“未能验证”，不扣信誉。报价、来源、预测、来访计划与随机状态随存档保存，重复交谈或读档不重抽。旧版已购线索继续保留，不追溯发放纸条或日历提醒。

## 配置与保存

首次启动从打包的默认配置创建 `<游戏>/UserData/MelonModTemplate/market-config.json`。可以修改公司、类型别名、交叉权重、事件影响、身份规则、手续费与上限。`RumorPrice` 默认 50，`RumorHorizon` 默认 3，`BrokerCooldownDays` 为旧版自动来访设置，当前电话预约不使用该冷却；`RequireSaveReloadVerification` 默认 false，按当前配置重新决定交易权限，存档中的旧 false 不会一直锁住功能；旧配置仍可读取。已有配置不会被构建覆盖。公司 ID 需要稳定，不要删除仍有持仓的公司；非法配置会停止初始化，保留原文件。

全部投资状态和原版资金共同保存在 `PlayerStore.modData["probably_stolen.stock_market.v1"]`。不使用独立持仓文件。交易失败会补偿现金和持仓；补偿或重写旧状态失败时冻结交易。

股市入口使用原生 postit 和存档内唯一编号识别，普通便笺不受影响。发放入口为 `EmporiumEntry.invElement`，需要确认主背包窗口实际绑定，并在插入后核对父容器和直接成员。成功后锁定本次会话，空查询不再触发自动造物；旧编号缺失时使用 `Ctrl+F8` 显式恢复。独立 PNG 通过原生解码、CPU 最近邻缩放和原生纹理上传注册图集，保留透明度及原版占位。图集载入后会显式刷新真实与拖拽 Image，并处理 overrideSprite；日志只有在两个 Image 的实际精灵指针一致时才报告 renderer readback。保存前还原原版资源路径，保存后重新应用图标。缺图时回退便笺图像。

## 验证与代码结构

```sh
dotnet run --project Tests/StockMarket.Tests
dotnet run --project Tests/TerminalGraphics.Tests
dotnet run --project Tests/TerminalGrant.Tests
dotnet run --project Tests/ChartInteraction.Tests
python3 MelonModTemplate/tools/verify_deployment.py
```

独立测试使用 .NET 10 SDK，覆盖交叉分配、行情去重、资金回滚、真假内幕、信誉、隐藏信息、存档隔离、事件推导、日 K 线累积、分时顺序与完整保存及旧档迁移；包含随机跳价日与预热固定、提前结束取消大跳、随机保留、永久估值锚点、多事件限幅、跨日补算和分币报价边界，以及电话次日预约、固定计划、来源匹配、逐公司核实和交付状态。另有 10 个图像采样场景和 33 项道具发放断言，覆盖透明缩放、满背包、重复查询和不确定插入。图表另有 23 项交互边界检查，覆盖单点、多点、14 日槽位、裁切和提示框边界。部署验证使用临时目录，不写入实际游戏。

`Market/` 为不依赖游戏的领域逻辑；`Game/` 负责原版接口、Harmony 补丁和存档；`UI/` 为游戏 CustomUI 原生面板；`Contracts/` 限定界面命令入口。`ModEntry` 成对订阅与解绑，并只清理本模组拥有的补丁和图像资源。

进一步的静态证据、适配限制和实机步骤见 [游戏适配说明](Game/ADAPTER-NOTES.md) 与 [原生界面说明](UI/NATIVE-NOTES.md)。游戏启动和实际游玩由使用者验证；编译成功不代表原生调用顺序和存档持久化已验收。

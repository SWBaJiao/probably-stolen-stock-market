# 股市 Mod 开发与使用

程序集为 `ProbablyStolenStockMarket.dll`，模组显示名称为 `Probably Stolen Stock Market`，版本 `0.16.0`。使用正式版内置加载器；Demo 目录中的旧版本保持独立，迁移后继续识别原有股市存档。

## 安装与构建

目标环境为正式版 Windows x64 Mono，本机接口依据为 Steam Build 26284217 / Unity 2021.3.45f2。项目目标为 `netstandard2.1`，引用正式版 `Probably Stolen_Data/Managed/`，由游戏提供 Harmony、Unity、TMPro 和 Newtonsoft.Json。其他构建需要重新核对游戏接口。

复制 `Game.local.props.example` 为 `Game.local.props` 并填写游戏目录。CrossOver 下填写 macOS 可访问的容器目录，不填写 Windows 的 C 盘路径。本地配置、生成 DLL、缓存和游戏代理均不提交到 Git。

```sh
dotnet build ProbablyStolenStockMarket/ProbablyStolenStockMarket.csproj -c Release
```

引用均不随模组复制，不需要额外安装加载器或生成 IL2CPP 代理。输出自动部署为：

```text
<正式版>/Mods/ProbablyStolenStockMarket/manifest.xml
<正式版>/Mods/ProbablyStolenStockMarket/ProbablyStolenStockMarket.dll
<正式版>/Mods/ProbablyStolenStockMarket/Assets/market-config.default.json
<正式版>/Mods/ProbablyStolenStockMarket/Assets/Textures/Items/stock_market_terminal.png
```

只构建加 `-p:DeployOnBuild=false`；复制调试符号加 `-p:DeployDebugSymbols=true`。构建不会启动游戏。

## 第一次使用

创建存档时可在原版职业／开局列表选择“负债店主”：你曾想靠炒股赚一笔，却亏掉大半积蓄并背上债务，如今决定重新经营店铺还债。与其他开局互斥，部分基础教程由原版 `skipIntro` 流程跳过。初始现金总额为 1500 元，已有固定旧债 5000 元，无利息、罚息或宽限。首个营业日起有完整 28 个游戏日，最后一天日结在普通服务付费后自动结清剩余旧债；现金不足则触发“抵债停业”。例如第 1 日开始，最后还款日为第 28 日夜间结算，不会提前到第 27 日结束。

电话 **731207** 开局即可查账、部分还款或提前结清；欠款期间不能再申请贷款，清后恢复普通贷款业务。名片在柜台空间可用时交付。规则、现金、债务和期限在原版首次保存前一起写入；读档不会重复发钱或延长期限。开局债务的还款和最终判定独立于股市交易验证及普通贷款开关，仍使用相同的现金核对与事务回滚。

开局初始化的独立边界检查为 `dotnet run --project Tests/StartingDebt.Tests`，领域检查为 `dotnet run --project Tests/StockMarket.Tests`。它们不启动 Unity，原版列表渲染、教程与实际保存流程仍需游戏内验收。

1. 在游戏“模组”菜单启用 `Probably Stolen Stock Market` 后重启。第 3 天营业时，证券开户专员林澈会到访，支付 50 元开户后领取“股市面板”。可以选择“三天后再来”，直接遣散也会延期三天。
2. 面板依次尝试放入背包、桌面和窗外，双击道具打开。窗外的面板请在保存或结束营业前收好，该区域不随存档保存且会在睡眠时清空。开户只收费一次；已开户后面板丢失，可在游戏中按 `Ctrl+F8` 免费补领，补领前会扫描现有面板，避免重复创建。旧存档已有面板时保留开户资格。现货交易默认开放，可以直接买入和卖出已持有股票。
3. 检查 `[股市交易]` 的可交易状态。默认无需首次保存重读；`RequireSaveReloadVerification=true` 可启用严格验证，要求保存后重新载入。余额不足、无持仓或资金补偿失败时显示具体原因。
4. 卖出或买入商品，成交与遣散后股价应保持不变；进入次日后观察昨日成交量引起的轻微变化。股票操作和情报费不会计为商品交易，事件按固定的行情日程独立影响价格。

窗口关闭可点击“关闭”或按 Escape。`Ctrl+F8` 只请求补领道具，不直接打开交易窗口。面板显示期间阻断主要原版买卖、拖拽及顾客操作，关闭后恢复鼠标状态。最终输入穿透情况仍需游戏内验证。

面板通过游戏的 `CustomUIManager` 和 `CustomUIBuilder` 创建独立原生窗口。优先使用已有控件预制件；缺少 SDK 模板时，以原生 UGUI 控件和游戏已加载的窗口、按钮图像及 TMP 字体建立本 Mod 的通用模板。行情、持仓、内幕、流水和市场新闻分为五个页面，交易仍通过原有资金和存档门控接口提交。

文字优先沿用游戏预制件的 TMP 字体和样式；中文覆盖检查及本窗口的字体回退记录在原生面板日志中。原生控件初始化、实际大小和输入效果需要在当前游戏中验证。

弹窗采用不透明深蓝背景、浅白正文、浅蓝标题及选中边框。按钮区分普通、选中、悬停、按下和禁用状态，禁用文字仍保持可读；涨红跌绿，可交易状态为绿色，不可下单原因与操作提示为黄色。图表、坐标和悬停框使用相同主题，悬停正文为 14 号字并带浅蓝细边框。

行情页在宽屏显示左侧公司列表及右侧图表与委托，公司列表独立滚动；窄屏使用紧凑公司选择区。图表按窗口剩余高度伸展，委托数量、买卖和确认按钮固定在行情页内，减少滚动才能交易的情况。持仓卡片按宽度分为一列或两列。图表仅保留“近 7 日、近 14 日、近 30 日”，当日分时入口与视图已移除，已有存档兼容。

7/14/30 日继续使用日 K 线，显示开高低收、影线和当前价线。上涨红色、下跌绿色、平盘灰色；旧存档及首次盘中接入日只显示灰色收盘标记，未知开高低为 `—`。正常后续游戏日开始积累完整 OHLC；当天尚未收盘的记录随实际行情继续变化。

鼠标移入图表绘图区可查看游戏日与开高低收。旧档未知值保持 `—`，当日记录标注未收盘。提示按帧响应并限制在窗口内，离开、切换或关闭窗口后隐藏。

持有股市面板后，系统自动向主物品栏发放“股市情报名片”，写明预约电话 **731206**、电话簿入口、确认后次日随机安排闻舟或剑清酱，以及情报需要付费且有真假。已有存档升级后也会补发一次；满包时延后，保存读回和切档不重复创建。名片仅提供联系方式，预约权限继续要求实际持有本存档的股市面板。阅读时正文跟随当前游戏语言，图像只包含电话号码，可用于四种语言。

## 公司和商品

默认 10 家公司：丰禾供给、清泉循环、白塔医疗、星锻工业、远星科技、环宇商贸、霆光能源、晨星物流、安盾防务、聚合材料。

行情页点击当前公司名称旁的“介绍”按钮打开独立窗口，每家公司以一段故事介绍主营商品、交叉业务与行业联系，不再显示商品影响比例明细。介绍和公开消息在弹窗中滚动阅读，可用“上一家／下一家”切换；入口与公司名称、现价同排，弹窗不再挤占 K 线与委托区域，Escape 先关闭介绍。已有配置中仍与旧版默认短介绍完全一致的内容会在加载时升级，自定义介绍保留；商品影响权重继续用于内部行情计算。

商品只按真实类型映射，不通过显示名称猜测。已核实类型包括 FOOD、WATER、MEDICAL、MACHINE、MATERIAL、BASIC_MATERIAL、MODULE、ENERGY_CELL、CHEMICAL_SUPPLIES、LUXURY_ITEM、WATER_PURIFICATION_SUPPLY、FILTER、WEAPON。空瓶如果没有 WATER 类型，不会自动算作饮用水。

同一分类内多个标签只算一次；命中多个分类时平均各行权重，总影响不随标签数量增加。成交以真实资金变化及调用范围确认，嵌套回调去重；无法确认的成交记录探针并跳过。

成交以实际成交金额衡量交易量，按商品权重累加当日各公司的净信号，玩家卖出为正、买入为负，同日跨顾客买卖先抵消。新一天只结算前一天的信号，采用 `TradeDailyLimit × 净信号 / (SignalScale + |净信号|)` 递减计算，默认成交影响上限为 ±2%；再叠加基础波动与估值回归，常规日变动合计限制在 `DailyLimit`，默认 ±3%。事件按独立日程变价，大跳不受常规日上限限制。未遣散顾客的已成功成交也计入当天，保存重载和重复日期回调不重复结算。升级旧档仅迁入仍未结束会话的待结算信号，旧版已结算行情不追溯重算。

新增配置 `TradeDailyLimit` 默认 0.02，旧配置缺失时使用此默认值；`CustomerLimit`、`RetailDailyLimit` 仅保留旧配置兼容，不再控制行情。股票初始价 100，手续费 0.5%，最低 1 游戏币；买入支出向上取整，卖出净收入向下取整。

事件激活时会固定一份行情计划：在当前可观察日到实际预计最后持续日之间，均匀随机选一天集中大幅跳价，包含当天，整次事件最多一次。持续 3 天的事件可能在第 1、2 或 3 天大跳；未知时长或永久事件使用 `EventShockWindowDays`，默认前 5 天窗口。此前每天以默认 65% 的概率轻微预热，幅度为配置冲击的 5%，单事件最多 0.5%；大跳当天不再预热或延续，之后按配置冲击的 10% 小幅延续，单事件每日最多 0.75%。预热和延续共用配置冲击幅度 25% 的累计预算。

事件实际结束后，从下一游戏日逐步消退，每天尝试修复剩余可消退影响的 25%；同公司所有事件的预热、延续与修复共用每日 ±1% 上限，大跳另用同公司每日 ±15% 主冲击限额。如果事件在计划大跳前结束，取消尚未发生的大跳，只对已经发生的预热做部分修复，不在结束后补跳。

每次事件只抽取一次 20%～50% 的保留比例，同一事件涉及的公司共用该比例，比例与实际已施加的偏移随存档固定。结束后保留这部分长期影响，利空留下折价、利好留下溢价。例如只看总计 −10% 的事件影响，最终保留 2%～5% 的折价；其他成交、日常波动和事件仍独立影响实际价格。估值回归基准包含已保留的事件因素，不会继续把它全部修复到最初的 100。回归仅消退该次事件的偏移，不回撤商铺成交或其他事件造成的变化。

可配置 `EventShockWindowDays`、`EventPreheatChance/Scale/Limit`、`EventRetentionMin/Max`、`EventContinuationScale/Limit/Budget`、`EventRecoveryRate` 和 `EventDailyDriftLimit`。大跳日、预热随机结果和保留比例随存档固定，不因读档或重复激活重抽；重复日期不追加同日影响。真实激活列表决定持续或结束状态，原版持续 3 天即生效日和之后两天，不多续一天。旧版已经完成首冲的事件按已跳价迁移，不重新排大跳；缺少旧冲击明细时只跟踪升级后的新增影响。

价格保留两位小数；极低股价若最小 0.01 的变化已超过日上限，修复会暂缓，等待后续价格允许，不突破上限或记录未实际发生的回撤。

原版事件内幕仍按原事件是否实际发生及其影响方向核验，不等待股市集中跳价。专用企业事件则以已排定的公开／主冲击日核验，使购买后未来三日窗口与事实公开一致。未公开时不会展示内部日期或目标价格。

## 事件与内幕

0.12.0 新增 20 个专用企业事件，与原版事件并存，只影响股票。详细数值、日程、交付和验收见 [股市专用事件](../docs/STOCK-EVENTS.md)。独立日程在正常日期推进时生成，电话和购买只查询已有计划；每 2～4 日一条，提前排定未来 7 日，同模板冷却 14 日。每次统一抽取 80%～120% 强度、2～4 日持续区间及主冲击日，分别保存，不受电话抽人或报价随机调用影响。

主冲击当日公开企业新闻，并核验专用事件内幕；此前界面、流水和 K 线原因仅显示匿名市场异动。原版快照只管理原版生命周期，专用事件不会因原版列表缺少其 ID 而结束。主冲击真实施加的份额按公司记录，后续恢复不会回撤被限幅挡掉的影响。已主冲击旧事件仍保留其历史快照。

“市场新闻”展示已公开的专用事件、关联公司和阶段，公司独立介绍同步展示相关新闻。内幕档案仅使用已购安全投影，显示来源、购买日、观察窗口、原始正文和核验对照；柜台已交付纸条重新阅读、以及日历点击，都使用同一份最新安全内容。未来事件 ID、精确排程日和内部真假标记不进入普通 UI。

显式事件规则优先。默认配置 `badNutrifruitHarvest`、`bm_illegal_weapon_shipment`、`rev_mobilization_secret`。未知事件如果带真实 `negociationDatas.itemType/value`，会按商品价格冲击与公司交叉权重反向生成影响：`-商品价格修正 × 公司权重 × StructuredEventScale`，单家公司限制在 `StructuredEventLimit` 内。商品涨价代表相关股票利空，降价代表利好；这是本 Mod 的玩法规则，具体企业的受益或受损关系可使用显式规则覆盖。没有结构化价格数据或商品映射的未知事件不猜测影响。

0.10.0 将默认动员事件改为利空，原版商品价格读取依据见 [适配记录](Game/ADAPTER-NOTES.md)。旧配置只有完整匹配原出厂动员规则才在内存中升级，不改写用户文件；编辑过的规则继续优先。自动规则带来源与方向版本，旧事件尚未大跳时仅修正未来冲击方向，保留已有实际因子、耗用预算、冲击日期及随机结果；已大跳事件继续旧快照的延续和部分消退，历史行情不重算。受调整影响的旧待核实线索改为“未能验证”，未购买报价过期，不改已购正文、已验证记录或来源信誉。

持有本存档的“股市面板”后，关闭股市窗口，在原版电话簿点击“行情消息专线”快速拨号，或手动拨打 **731206**。拨通后出现原生确认窗口，点击“预约明日到访”才随机安排闻舟或剑清酱；取消、挂断、重拨或切档都会使旧确认失效，已经确认的预约不会因重拨换人。电话听筒状态栏只显示“通话中”，详细反馈写入日志；可在“内幕档案”查看号码与预约状态。原面板邀请按钮已移除，掮客不再自动来访。

预约当下按次日到访后的未来 3 日窗口选择已有排程事件，固定来源、报价、真假及外观。例如第 41 日拨号，预约第 42 日，只考虑第 43～45 日的有效关联事件；没有可售线索就不会预约。重复拨号与保存重载不重抽，次日开门后追加到顾客队尾。错过日期或线索取消会显示失效，完成并遣散后可以预约次日。

掮客显示为“闻舟 · 行情掮客”，初次实际见面会自我介绍，介绍状态随存档保留；电话联系不会提前标记见过面。介绍后打开原版情报购买窗口，默认 50 游戏币；付款前只展示消息来源、商品类别与价格。内幕购买默认开放，权限与股票现货交易一致，没有额外的强制保存重读要求；余额不足、过期、已购买或资金失败冻结时不能付款。普通顾客不提供股市报价。电话只接管专号，快速拨号条目仅是临时 UI，不写原版联系人存档，也不向原版未来顾客队列写入专属 ID。

购买后给出商品关联型或指定公司型的股票涨跌预测，不同公司可以方向不同；真假内容句式一致，假消息反转预测方向。掮客转售的消息归属于实际来源；当前没有可确认稳定的个人身份，因此信誉按角色类型和阵营累计，并在界面标注。来源必须匹配披露行业或为泛来源，历史验证记录会更新信誉。

付款成功即保存购买记录，在购买次日起连续三日登记日历提示。成交对话末句提供原生 `handnote` 纸条，使用柜台交付及游戏纸张阅读界面；柜台满时等待空位，跳过对话、遣散或读档后仍走同一交付入口。插入结果不确定时停止重复创建。纸条丢失不影响档案和日历，点击日历仍可阅读。

日历只添加 Mod 显示记录，不改变真实事件排程、公开状态或价格影响。事件发生后按其对目标公司的实际影响方向判定属实或失实，一条多公司情报只更新一次来源信誉。取消或无法核实记为“未能验证”，不扣信誉。报价、来源、预测、来访计划与随机状态随存档保存，重复交谈或读档不重抽。旧版已购线索继续保留，不追溯发放纸条或日历提醒。

## 贷款

放款后自动打开纸质合同，并在原版日历的放款日、到期日、最后还款日添加提示。点击贷款日程，或拨打 **731207** 后选择“打开贷款合同”，可重新查阅。结清后移除活动贷款日程，电话保留最近一份已结清合同；原有旧档中已经结清的合同无法追溯补出。开局旧债使用“旧债确认书”，日历仅在第 28 个营业日的最后还款日显示提示，不展示每日还款期倒计时；日历尚未覆盖期限时，可通过贷款专线随时查看完整合同。

合同采用旧象牙纸、酒红标题与无文字的朱红天平圆章。签约条款保存本金、利率、期限、抵押及逾期处理约定，即时账单另列当前本金、利息、罚息和结清状态。右下角保存签约时 Steam 昵称，读取失败或旧档缺失时使用“店主”；读取不主动初始化 Steam，改名不会改写已签合同。

每日服务结算界面中，所有已解锁、未冷却且价格大于零的服务单价都高于当前现金时，记录首次资金危机，次日正常营业后安排沈衡优先到访。只要还有一项付费服务能够承担就不触发；余额与某项价格相等时也不触发。首次介绍完成或直接遣散后留下联系方式和名片，电话号码为 **731207**，名片丢失或柜台满不影响电话业务。触发不会修改原版服务的选择、扣费或结束当天条件。

令 S 为近三个有记录游戏日的服务应付总额平均值，同日保留已观察的最大应付费用，包括触发时未能支付的部分。旧档不补造历史，不足三天时使用已有记录。无抵押本金上限为 min(5S, 500)，S 为零时基础额度 100；股票抵押上限为 min(20S, 2,000, 所选股票估值×50%)。股票单股估值取当前价与最近完整交易日收盘价的较低值，没有可靠历史收盘价时暂不接受抵押。

贷款期限可输入 1～28 天，并提供 7/14/21/28 天快捷选项。1～7、8～14、15～21、22～28 天的无抵押日利率分别为 2%、2.25%、2.5%、2.75%，抵押日利率分别为 1%、1.25%、1.5%、1.75%。按剩余本金计算单利，放款当天不计息，签约后利率固定；提前结清沿用签约利率，不重新按短期档位计算。内部保留小数，结清金额统一向上取整。

同一时间只能有一个未结清合同，逾期和清算后的剩余欠款仍占用名额。电话可查询、部分还款和全部结清，还款顺序为罚息、普通利息、本金；抵押股份全额结清后统一解锁，普通卖出只允许出售未锁定部分。合同最终确认会重新核对日期、报价及抵押数量，变更后须重新确认。

到期日为 D：D+1、D+2 为宽限期，D+3 开始正式违约。无抵押贷款按剩余本金每日增加 0.5% 罚息，累计最多为原始本金的 10%；抵押贷款按市价处置抵押股票并扣正常手续费，多余退回，不足部分继续追缴。D+7 仍可营业还款，D+8 开始时仍有欠款则进入“抵债停业”结局。部分还款不会推迟期限。到期前一天、D+5 和 D+7 提供空闲时可见提醒，正式逾期后贷款专员每隔两天催收。

结清后等待三个游戏日才能重新申请。正式违约会记录一次信用受损，下一笔无抵押额度降为 75%，正常结清这一笔后恢复。额度、利率、宽限期和处罚默认值可在配置的 `Loans` 中调整，已签合同保存条款快照，修改配置不改变旧合同。最长四周指正常合同期限，逾期处理期另计。

## 配置与保存

剑清酱与闻舟共用 **731206** 行情消息专线，电话簿只提供一个临时快速拨号入口。确认预约后等概率选取其中一人次日到访，来访前不在电话中透露人选。重复拨号复用现有预约，同日取消、错过或报价失效后不重新抽人；没有可售线索时不安排来访。两人的预约、来访、首次见面和报价状态仍独立，沿用原生购买、纸条与日历流程。旧存档的闻舟预约继续有效，无需重开存档。

剑清酱以本人身份提供消息，个人信誉独立累计，闻舟继续转售各类来源的消息。`JianqingReverseProbability` 默认 `0.70`，每条新消息以 70% 概率将真实事件对各家公司的影响逐项取反，另有 30% 概率给出一致方向；同一条涉及多家公司的情报共用一次真假结果。可设为 0～1，行业加成和历史信誉不改变这个固定概率，实际次数不保证严格每十条七条反向。验证依据仍是事件事实及作用方向，不以其他因素造成的最终股价判断；事件取消或无法核实不扣信誉。报价生成后真假、正文与概率快照保存固定，重读或修改配置不重抽旧报价，配置只影响之后的新报价。

两张人物图位于 `Assets/Textures/Characters/`：`jianqing.png` 保留照片中的短发、眼镜、深蓝上衣及斜挎包；`wenzhou.png` 使用兜帽、面罩和长外套完全遮脸。运行时把 PNG 以最近邻适配原版人物精灵的大小、锚点及像素密度，注册独立键，不覆盖游戏人物资源。图像加载失败会记录原因并退回原版人物素材；实际柜台比例、遮挡和对话显示由游戏内验收。

首次启动从打包的默认配置创建游戏持久化目录下的 `ModData/probably_stolen_stock_market/market-config.json`，日志会打印实际路径。旧 Demo 配置可手动复制到这里，覆盖前先保留现有配置。可以修改公司、类型别名、交叉权重、事件影响、身份规则、手续费与上限。`RumorPrice` 默认 50，`RumorHorizon` 默认 3，`BrokerCooldownDays` 为旧版自动来访设置，当前电话预约不使用该冷却；`RequireSaveReloadVerification` 默认 false，按当前配置重新决定交易权限，存档中的旧 false 不会一直锁住功能；旧配置仍可读取。已有配置不会被构建覆盖。公司 ID 需要稳定，不要删除仍有持仓的公司；非法配置会停止初始化，保留原文件。

全部投资状态和原版资金共同保存在 `PlayerStore.modData["probably_stolen.stock_market.v1"]`。不使用独立持仓文件。交易失败会补偿现金和持仓；补偿或重写旧状态失败时冻结交易。

股市入口使用原生 postit 和存档内唯一编号识别，普通便笺不受影响。发放按背包、桌面、窗外的顺序选择可用位置，插入后核对父容器和直接成员。开户状态与交付状态分别保存，补发或丢失补领不重复收费。空查询不触发自动造物；已开户且面板丢失时使用 `Ctrl+F8` 显式恢复，补领前扫描所有现有面板。独立 PNG 通过原生解码、CPU 最近邻缩放和原生纹理上传注册图集，保留透明度及原版占位。图集载入后会显式刷新真实与拖拽 Image，并处理 overrideSprite；日志只有在两个 Image 的实际精灵引用一致时才报告 renderer readback。保存前还原原版资源路径，保存后重新应用图标。缺图时回退便笺图像。
